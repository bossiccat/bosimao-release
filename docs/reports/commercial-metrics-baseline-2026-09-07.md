## 1. 一页结论

| 指标族 | 门禁标准（P50/P95/P99） | 当前状态 | 判定 |

| TTFP（用户说完 → AI 首音） | ≤ 500 / 800 / 1200 ms | **未实测**（无端到端分位数样本） | **不可判** |

来源：team-lead 派工简报 2026-09-07（对应任务 #37 定义 GPT Live 质量门禁 / #41 冻结严格 GPT Live 语音质量验收矩阵）。

| 指标 | P50 | P95 | P99 | 说明 |
|------|-----|-----|-----|------|
| **TTFP** Time-To-First-Phoneme | ≤ 500 ms | ≤ 800 ms | ≤ 1200 ms | 用户说完 → 听到 AI 第一个音 |
| **TTS TTFB** | ≤ 300 ms | ≤ 500 ms | ≤ 800 ms | 云端首字节/首帧 |
| **barge-in** 开口 → 停播 | ≤ 100 ms | ≤ 150 ms | ≤ 250 ms | 用户一开口，AI 播放必须停 |

**关键判读**：本轮唯一确认的延迟事实是 **M3 = 10.1 s**（response.created → 手机 firstAudioFrame）。
这个数已实锤，但**拆不开**：

- 本地侧各跳耗时**无可引用的实测数据**，无法算出任一子段占比；
- 手机侧 L5（`onFirstAudioFrame`）**未接入** F6/F7 trace 体系，无法区分「帧没送到手机」与「帧到了但被 SDK 缓冲住」。

因此 M3 覆盖的区段（下行丢弃窗口、TRTC 传输、手机 SDK jitter buffer）**至今一条都判不死**。
补齐 L5 + 拿到一次真实会话，10.1 s 就能一次拆开。

## 5. 取得门禁样本的前置条件

按依赖顺序，缺一不可：

1. **无线 ADB 打通**（当前阻断，见主报告 §环境阻断项）
   —— `adb connect 100.75.48.99:46813` → `10061 主动拒绝` = 手机端无线调试未开，需用户操作。
2. **真机取证 SOP 执行**（`docs/reports/device-capture-sop-2026-09-07.md`）
   —— 拿到对时基准 + 30 s 会话采样 + 电平样本。
3. **F6/F7 逐帧 trace 上线**（`af08c8f` + `e8b854f` 已合入，Android 侧 L5 未接）
   —— 否则 TTFP 拆不出分段，只能得到一个总数。
4. **日志持久化**（`3e39bb6` 已覆盖 rtc_bridge/relay）
   —— 否则样本随进程重启再次丢失（M3 的教训）。
5. **重复采样 ≥ 30 轮** —— P95/P99 需要分布，1~2 次会话给不出分位数。
