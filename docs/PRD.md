## 1. 产品定位

**一句话定位**：你的 AI 编程 agent 们的**大脑 + 管家 + 远程指挥**——看懂屏幕、听懂意图，把"你想要什么"翻译成对 Codex/Trae/Hermes/WorkBuddy 最有效的指令拆解，确认后注入执行；管理多 agent 并行任务；你不在电脑前也能接收报告、远程指挥。

**核心卖点（用户最大痛点）**：**意图 → 最优指令拆解**。用户"自己给 Codex 下指令下不好"，贾克斯理解会话 + 任务 → 拆解 → 生成最优指令 → 确认后注入 Codex。这是本产品区别于所有"监控提醒"工具的根本价值，监控/判定/提醒是支撑该价值的能力，而非终点。

**产品形态**：Windows 桌面常驻的「宠物形 AI 智能助手」，**混合大脑** = 本地 MiniCPM-O 4.5 多模态 9B（监控/视觉判定/轻量理解）+ **DeepSeek V4 Flash 正式版 API**（任务拆解/评审/指令生成，云端）。省钱到极致：仅会话摘要上传云端，截图不出本机（延续 O-006 脱敏）。

**被监控/被指挥对象**：Codex（开源桌面版，重点监控，CLI 未装）/ Trae / Hermes / WorkBuddy 四目标（用户桌面实测均在跑，均为桌面端 App，有实时会话窗口）。

**安全边界（受控注入，O-013 用户裁决）**：注入前用户确认；注入内容仅指令文本（不读 Codex 内部数据、不键鼠模拟 UI 之外的操控）；截屏不出本机；上传云端仅会话摘要且脱敏。详见 §5.4。

**推送隐私边界（O-006 用户裁决）**：本地分析全程在本机完成（本地隐私承诺）；离开本机的数据为两类——①即时提醒/报告消息：仅**脱敏摘要文本**（app_id + 状态 + ≤20 字摘要 + 建议），**不附截图、不含代码片段、不含文件路径**；②V1.5 起大脑闭环的**会话摘要**（供 DeepSeek 拆解，脱敏后上传）。webhook URL 仅存于 `.env`，不入库、不随配置落盘。推送为即时通知，内容即发即弃，不做云端存储/分析。

## 2. 价值主张与市场空白

### 2.1 核心价值主张

1. **意图→指令拆解（差异化核心）**：用户不会给 AI 下指令，贾克斯会。本地 9B 理解会话上下文 → DeepSeek 把意图拆成 3-8 步可执行任务 → 生成对 Codex 最有效的指令文本 → 用户确认后注入。现有工具最多给"建议文本"让用户自己复制粘贴，贾克斯把"生成→确认→注入"闭环做进产品。
2. **多 harness 管家（V2）**：管理 Codex/Trae/Hermes/WorkBuddy 并行任务——任务队列 + 依赖编排，前驱失败不误启动后继，跑偏/卡住自动重试或通知。
3. **远程指挥（V1.5 单向报告 → V2 双向）**：电脑→手机脱敏报告（V1.5）；手机→电脑云端中继加密指挥（V2）。人不在电脑前也能安排/验证/测试/QA。

### 2.2 市场空白（4 条差异化支撑）

1. **截屏级视觉监控**：现有监控工具全部依赖 agent 日志/telemetry/OTEL，Trae 这类 GUI 应用不暴露结构化日志——现有工具全部监控不了。本项目用本地多模态模型读屏幕，可监控任何桌面应用且无需 agent 配合改造。
2. **内容级跑偏检测**：现有工具只判断 running/idle/stuck（状态机），不能"看懂"agent 输出内容是否改错方向、陷入死循环。MiniCPM-O 可做语义级判断——现有工具全都没有的能力。
3. **主动打扰式提醒**：现有工具全是"你主动打开 dashboard 才看得到"。本项目是宠物主动说话 + 桌宠动效 + 手机推送。
4. **本地隐私**：会话日志含代码/API key，本地处理是强诉求；Agent Watch / LangSmith 均上云。混合大脑下截图全程不出本机，仅脱敏会话摘要上云。

## 5. 版本路线与 MVP 范围

**主线：V1（监控闭环）→ V1.5（大脑闭环）→ V2（管家 + 远程指挥）**；V1.1 全双工语音为 V1 后段里程碑（M1 PoC 通过后并入，O-001 待裁决）。

### 5.1 V1 监控闭环（MVP，可验收）

1. 屏幕截屏 + 本地多模态分析（对 Codex/Trae/Hermes/WorkBuddy 四目标窗口定时截屏，MiniCPM-O 理解"当前在干什么"）
2. 跑偏/卡住/关键进展检测 + 主动提醒（桌宠动效 + 系统通知 + 语音播报）
3. 手机推送（企业微信 webhook 主选 + ntfy 备选，Provider 插件化）
4. 基础宠物形象（有机光球，监控态/提醒态双形态）

> **V1.1 全双工语音**（M1 PoC 通过后开发，并入 V1 后段）：原生全双工语音对话（能听能说能打断，类 GPT-Live 体验）+ 语音六态状态机前端对接 + silero-vad 门控 + 兜底降级链（sherpa-onnx + edge-tts）。

### 5.2 V1.5 大脑闭环（核心价值落地，2026-08-03 用户拍板）

1. **意图理解**：本地 9B 理解当前会话上下文 + 用户自然语言意图，生成**脱敏会话摘要**（截图不出本机，延续 O-006）
2. **任务拆解 + 指令生成**：DeepSeek V4 Flash 正式版 API 将意图拆解为 3-8 步可执行任务清单（含目标/验收点/回滚提示），组装为对 Codex 最有效的指令文本并预览（O-011 混合大脑）
3. **确认后注入**：生成 → 用户确认 → 自动注入 Codex 输入框（O-012 默认；全自动注入留 V2）
4. **单向报告**：电脑 → 手机（会话摘要 + 状态 + 脱敏建议）
5. 隐私延续：仅会话摘要上传云端，截图不出本机

### 5.3 V2 管家 + 远程指挥

1. **多 harness 并行编排**：管理 Codex/Trae/Hermes/WorkBuddy 并行任务——任务队列 + 依赖 DAG，前驱失败不误启动后继，失败重试/降级/通知
2. **双向远程指挥**：手机 → 电脑（云端中继加密；断线续传，电脑端任务不中断，恢复后自动同步）
3. **全自动注入**（可选演进，O-012 留 V2，需用户确认边界）

### 5.4 安全边界：受控注入（O-013，2026-08-03 用户裁决）

从"只监控不操控"升级为"**受控注入**"，四点边界不可逾越：

1. **注入前用户确认**：生成 → 确认 → 注入，全程用户可见；未经用户显式确认，不注入任何内容
2. **注入内容仅指令文本**：不读 Codex 内部数据、不键鼠模拟 UI 之外的操控（仅输入框注入指令文本 + 触发发送）
3. **截屏不出本机**：视觉分析全程本地完成，截图永不上传云端
4. **上传云端仅会话摘要且脱敏**：延续 O-006，不含代码原文、文件路径、API key

### 5.5 明确不做清单

1. 不做注入确认之外的任何 agent 操控（不读内部数据、不键鼠模拟 UI 之外操控；安全边界=受控注入）
2. 不做 agent 日志解析/框架 SDK 接入（依赖日志的路线覆盖不了 Trae）
3. 不做云端 SaaS/账号体系（本地优先隐私）
4. 不做宠物养成玩法（喂食/升级/商店）
5. 不做 token 成本监控（非差异化）
6. 不做多语言/国际化
7. 不做推送内容的云端存储/分析——推送仅为即时通知，脱敏摘要即发即弃，不留存、不聚合、不用于训练

## 6. 功能需求（EARS 句式）

### 6.1 监控（M-*）

- **M-1**：WHEN 应用启动，THEN 自动加载 config/monitors.yaml 中的监控目标并按轮询间隔开始截屏分析。
- **M-2**：WHEN 被监控窗口可见，THEN 每 5-8s 捕获一帧并交给本地多模态模型分析，单帧端到端判定 ≤ 4s。
- **M-3**：WHEN 用户进入语音对话，THEN 监控轮询降频至 10-15s/帧。
- **M-4**：WHEN 被监控窗口最小化或捕获失败，THEN 降级为 DXGI 兜底或仅窗口状态监控，并记录降级原因。

### 6.2 检测与提醒（D-*）

- **D-1**：IF 某 agent 连续 3 帧判定状态不变 AND 持续超时 120s，THEN 判定为"卡住"并触发提醒（P50 响应 ≤ 2s）。
- **D-2**：IF 某 agent 判定为"跑偏"（内容级偏离目标），THEN 触发提醒并附建议。判定准确率以 PoC B1 固化的样例集（≥10 张真实截图人工标注）为验收基线。
- **D-3**：WHEN 提醒触发，THEN 按四级渐进打扰递进（**递进=按严重度定级，非时间累进**）：①状态点变色 → ②桌宠微动 → ③桌宠浮起放大脉冲 → ④语音播报 + 手机推送（仅 4 级）。分级规则：stuck 超时=4 级、off_track=3 级、恢复=1 级。
- **D-4**：WHEN 检测到恢复（状态变为有进展），THEN 自动清除卡住/跑偏状态并通知。

### 6.3 语音（V-*，V1.1）

- **V-1**：WHEN 用户点击宠物或按下唤醒键，THEN 进入 Listening 状态。
- **V-2**：WHEN 用户说话结束，THEN 端到端响应首字 ≤ 1.5s（原生全双工）。
- **V-3**：WHEN 宠物正在说话 AND 用户开口，THEN 500ms 内打断并进入 Listening（barge-in，变形不重置；"变形不重置"依赖 PoC B3 实测验证）。
- **V-4**：WHEN 原生全双工不可用，THEN 自动降级半双工（sherpa-onnx STT + edge-tts TTS），分轮回话 ≤ 2.5s。
- **V-5**：WHEN 静默超时（15s 无对话），THEN 自动回落 Monitoring 状态。

### 6.4 推送（P-*）

- **P-1**：WHILE 推送提醒时，系统必须仅发送脱敏摘要文本（app_id + 状态 + ≤20 字摘要 + 建议），不得附截图、不得包含代码片段或文件路径；WHEN 触发 4 级提醒，THEN 通过当前启用的 Provider 推送手机。
- **P-2**：WHEN 主 Provider（企业微信）失败，THEN 自动熔断切换备选（ntfy）。
- **P-3**：WHEN 推送成功/失败，THEN 记录到 metrics 日志供审计。

### 6.5 宠物 UI（U-*）

- **U-1**：WHEN 应用运行，THEN 宠物以透明窗口常驻桌面（监控态 64-96px / 透明度 20-40%）。
- **U-2**：WHEN 触发 3 级及以上提醒，THEN 宠物浮起放大至 120-160px 并以语义色 2Hz 脉冲。
- **U-3**：WHEN 系统开启 reduced-motion，THEN 全部动效降级为静态颜色 + 透明度变化。

### 6.6 意图理解（I-*，V1.5）

- **I-1**：WHEN 用户通过桌宠/面板以自然语言发起"帮我拆/帮我写/帮我做"类指令，THEN 本地 9B 提取用户意图并生成脱敏会话摘要（摘要不含代码原文/文件路径/API key）。
- **I-2**：IF 意图置信度低于阈值，THEN 向用户追问澄清，最多 2 轮后以最佳猜测继续并明示假设。
- **I-3**：WHEN 会话摘要生成完毕，THEN 仅将该摘要上传 DeepSeek V4 Flash（截图不出本机，延续 O-006）。

### 6.7 指令拆解与生成（C-*，V1.5）

- **C-1**：WHEN 收到用户意图 + 会话摘要，THEN DeepSeek V4 Flash 将意图拆解为 3-8 步可执行任务清单，每步含明确目标/验收点/回滚提示。
- **C-2**：WHEN 任务清单生成，THEN 自动组装为对 Codex 最有效的指令文本（含约束、目标、验收标准），并展示给用户预览。
- **C-3**：WHEN 用户对指令文本不满意，THEN 允许用户修改约束/目标并重新生成（重生成频率限 1 次/min 防刷）。

### 6.8 确认注入（N-*，V1.5）

- **N-1**：WHEN 指令文本已生成，THEN 进入待确认状态；未经用户显式确认，不注入任何内容（受控注入第一边界，O-013）。
- **N-2**：WHEN 用户确认注入，THEN 仅将指令文本输入 Codex 输入框并触发发送；不读取 Codex 内部数据、不执行 UI 之外的操控。
- **N-3**：WHEN 用户拒绝或修改后确认，THEN 以修改后文本为准注入，并记录注入审计日志（时间/目标/指令摘要）。

### 6.9 并行编排（O-*，V2）

- **O-1**：WHEN 多个 harness（Codex/Trae/Hermes/WorkBuddy）任务存在依赖，THEN 按任务队列与依赖 DAG 自动调度，前驱完成后触发后继。
- **O-2**：WHEN 某 harness 任务失败或卡住，THEN 按编排规则重试/降级/通知用户，不静默跳过。
- **O-3**：WHEN 用户从远程发起新任务，THEN 任务进入队列并按优先级插队或排队执行。

### 6.10 双向远程（R-*，V2）

- **R-1**：WHEN 手机端发送指令/查询，THEN 经云端中继（加密）到达电脑端执行，并回传结果。
- **R-2**：WHEN 电脑端状态变化（卡住/完成/异常），THEN 通过加密中继推送手机端（单向报告为 V1.5 基础能力）。
- **R-3**：WHEN 远程连接中断，THEN 电脑端任务继续本地执行，恢复后自动同步状态到手机（断线续传）。

## 10. 数据埋点方案

MVP + V1.5 必须埋点的关键事件（不埋 = 上线后无法验证产品假设，尤其是"意图→指令"核心价值）：

| 事件类别 | 必埋事件 | 说明 |
|----------|----------|------|
| 获客 | page_view, sign_up_complete | 新用户从哪来、注册转化率 |
| 激活 | first_core_action, intent_submit | 用户完成第一个核心操作（创建监控/发起第一次意图拆解） |
| 核心价值 | intent_parsed, instruction_generated, instruction_confirmed, instruction_injected | 意图→指令→确认→注入漏斗（核心假设验证：确认率/注入成功率） |
| 留存 | session_start, session_duration | DAU/MAU、使用频次 |
| 转化 | upgrade_click, payment_complete | 付费转化漏斗（如有） |
| 异常 | error_occurred, deepseek_api_fail, inject_fail | 前端 + API + 注入失败；混合大脑降级次数 |

> 埋点实现要求：前端轻量 SDK（Mixpanel / Umami / 自建 `trackEvent()` 封装）；事件命名 `{对象}_{动作}`（如 `instruction_confirmed`、`deepseek_api_fail`）；属性含 `user_id`/`timestamp`/`device`/`version`；不采集隐私数据（不上报 IP、不存原始输入内容、不采集截图）。
