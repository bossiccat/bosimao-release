# ADR-008: 监控策略 — 5-8s 轮询 + 3 帧不变 + 120s 超时

- 状态：已接受
- 日期：2026-08-03
- 决策者：架构师 高见远

## 背景

监控截屏频率与误判率需要平衡：帧太密浪费 GPU 与显存，帧太疏漏掉关键状态；误报（假卡住/假跑偏）会破坏用户信任。

## 决策

- 轮询频率：**5-8s/帧**（检测到活动变化 5s，平稳 8s）→ 约 37 次/小时 × ~1.5s ≈ GPU 占用 5-8%
- 对话期降频：**10-15s/帧**（显存时分复用，监控让位语音）
- 卡住判定：**连续 3 帧状态不变 AND 持续超时 120s** 双条件触发（防误判）
- 恢复：状态变为有进展即清除
- 阈值参数化：`config/detection.yaml`（frame_threshold / timeout_seconds / prompt 模板路径），改配置即生效
- 判定留痕：每次检测结果落盘，供回归集回放

## 后果

- 正面：GPU 占用低、误判有双条件缓冲、灵敏度可调
- 负面：卡住检测最多滞后 120s+；极小概率漏掉瞬时状态变化（可接受，宁漏报不误报原则）
- 替代触发条件：PoC B1 单帧判定 >4s → 降采样/降频 10s 重测；仍超标 → 混合监控方案
