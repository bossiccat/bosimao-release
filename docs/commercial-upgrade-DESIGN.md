# 商业版升级 Phase 1 设计基线

> 文档类型：Product Register 设计与交互契约
> 适用范围：Android 随身语音助手、Windows 桌面宠物、语音会话与提醒界面
> 当前裁决：原型可继续验证，但不具备商业发布条件
> 说明：本基线综合现有已确认设计规格与只读审计证据。`designer-final`、`architect-final` 因超过最大轮次失败，其未完成产出不作为本文件依据。

## 1. UI/UX 差距

当前体验未形成可信的商业闭环，核心差距如下：

1. 会话生命周期与用户可见状态未统一。签发、进房、退出和语音听说状态混杂，签发期间取消可进入永久退出锁。
2. 音频状态与播放订阅耦合。远端停止说话被错误实现为静音订阅，可能导致下一轮回复无声。
3. Android 核心路径缺少真实证据。现有测试不能证明手机采集、桌面处理、下行注入和手机播放完整闭环。
4. 错误恢复缺少用户可理解反馈。连接、签发、引擎和播放失败需要明确说明当前状态、恢复动作与是否保留任务。
5. 入口优先级必须清晰。P0 仅包含 Android 主会话页手动入口、悬浮球和前台通知；唤醒词仅为 P1 Beta，不得宣称“随时唤醒”。
6. 设计契约仍处于修复期。组件硬编码色、浅色主题、六态接线、提醒焦点管理需要在发布前完成机械验证。

## 2. 统一状态模型

状态必须拆成两个正交层，禁止以单个布尔值表达完整会话。

### 2.1 会话生命周期

`IDLE -> SIGNING -> ENTERING -> IN_ROOM -> EXITING -> IDLE`

- `IDLE`：未建立会话。P0 可从 Android 主会话页手动入口、悬浮球或前台通知按钮发起；唤醒词仅为 P1 Beta。
- `SIGNING`：获取短期会话凭证。用户取消时立即终止本地请求语义并回到 `IDLE`。
- `ENTERING`：凭证已取得，正在进入房间。取消后进入 `EXITING`，必须有超时兜底。
- `IN_ROOM`：双端媒体链路已建立，可进入听、想、说体验状态。
- `EXITING`：仅用于已进入或正在进入房间的退出流程。退出成功或超时后必须回到 `IDLE`。

未进房时禁止等待退房回调。所有状态转换串行处理，同一时刻只允许一个会话命令生效。

### 2.2 用户体验状态

`idle -> requesting_permission -> connecting -> listening -> endpointing -> thinking -> speaking -> idle`

- `idle`：未开始本轮语音交互；桌面宠物保持安静，Android 保留手动入口。
- `requesting_permission`：解释麦克风用途并等待用户决定，不循环弹系统权限框。
- `connecting`：建立媒体或服务连接，显示连接进度和取消动作。
- `listening`：采集用户语音并显示实时转写；主操作为“停止聆听”。
- `endpointing`：VAD 已检测到输入结束，短暂确认后进入思考；不得让布局跳动。
- `thinking`：等待模型响应，提供取消；不使用无限旋转或空洞文案。
- `speaking`：播放助手语音，主操作为“停止播报”，允许用户打断。
- `interrupted`：用户在播报或思考中开口时进入的瞬时 `experienceState`，先停止输出，再回到 `listening`；不得为打断流程新增第三套状态模型。
- `recovering`：可恢复故障的有限重试，显示倒计时与重试次数。
- `error`：不可恢复或重试耗尽，保留草稿/上下文并提供重试或转文字输入。
- 15 秒无有效输入回落 `idle`；提醒 `alerting` 只作为独立通知层，不改变语音体验状态。

### 2.3 聚合 UI 模型

架构会话生命周期与 UI 体验状态保持正交：生命周期仍仅允许 `IDLE/SIGNING/ENTERING/IN_ROOM/EXITING`，体验状态由本节状态机驱动。所有端只消费一个聚合 `VoiceUiModel`，禁止 `isListening/isThinking/isSpeaking` 等并行布尔状态。

```ts
type VoiceUiModel = {
  sessionLifecycle: 'IDLE' | 'SIGNING' | 'ENTERING' | 'IN_ROOM' | 'EXITING';
  experienceState: 'idle' | 'requesting_permission' | 'connecting' | 'listening' |
    'endpointing' | 'thinking' | 'speaking' | 'interrupted' | 'recovering' | 'error';
  primaryLabel: string;
  secondaryLabel?: string;
  primaryAction: 'start' | 'stop_listening' | 'cancel' | 'stop_speaking' |
    'retry' | 'open_settings' | 'switch_to_text';
  canCancel: boolean;
  canInterrupt: boolean;
  errorCode?: string;
  retryPolicy: { maxAttempts: number; backoffMs: number[] };
  draft?: string;
  context?: { conversationId?: string; lastUserTurn?: string };
};
```

`VoiceUiModel` 是跨 Android 与桌面的文案、主操作、恢复和可访问名称唯一来源；状态转换与会话命令串行处理，同一时刻只允许一个命令生效。

## 3. Android 与桌面交互

### 3.1 Android

- 主会话页顶部固定连接/设备状态，中部展示实时转写与助手回复，底部固定 56px 语音主控；状态变化不得导致控件位移。
- 以前台麦克风服务承载常驻监听，持续显示低优先级系统通知。
- P0 提供三种等价入口：主会话页“开始对话”、悬浮球轻触、前台通知“立即对话”。三者调用同一串行会话命令并进入同一 TRTC lifecycle；任一入口失败时，其他入口仍可用。唤醒词仅为 P1 Beta。
- Android 14 后台启动限制通过前台授权流程、自启动说明与电池白名单引导处理，不采用隐藏服务或双进程保活。
- 权限拒绝显示用途说明、“去设置”和“转文字输入”；不得循环弹系统权限框。
- 断网时保留实时转写草稿；恢复联网后由用户显式点击“继续发送”，不得静默重发。
- 音频设备占用时显示具体原因（通话或其他录音应用），提供“重新检测”；超时/服务失败保留会话上下文并提供“重试/转文字输入”。
- `speaking` 中检测到用户开口后，先把视觉状态切为 `interrupted`，≤300ms 停止播报，再幂等执行 `pause + flush` 并发送 `interrupt`，随后进入 `listening`。
- 悬浮球常态不遮挡内容；听与说时展开波形。波形只反映实时 RMS，不承担关键语义。
- 通知栏操作固定为暂停监听、立即对话、退出；Android 主会话页、悬浮球、通知操作及桌面所有可操作控件的触摸或点击目标均不小于 44 x 44px，并通过可访问性扫描。
- 应用重启只恢复未发送文本和最近会话，不自动开启录音。

### 3.2 桌面

- 宠物默认安静；单击或 Enter/Space 打开紧凑会话面板，宠物本体仅显示短状态，完整说明和操作集中在面板，避免重复 Toast。
- listening 显示波形与“正在听”；endpointing 显示“正在确认”；thinking 使用低干扰进度；speaking 显示“停止播报”主操作。
- 宠物锚点支持鼠标点击、Enter、Space 打开或关闭监控面板，并暴露 `aria-expanded`。
- 一级、二级提醒只改变状态点及图标；三级、四级显示提醒气泡。
- 提醒气泡支持关闭按钮与 Esc。打开时焦点进入关闭按钮，关闭或自动回落后焦点归还宠物锚点。
- 离线、鉴权、设备异常采用面板内联错误，显示具体原因、重试次数和恢复动作，不弹重复 Toast。
- 面板关闭不等于取消会话；监听中关闭需二次确认或先停止录音。重启仅恢复文本，不恢复录音。
- 远端静音、停止说话等 SDK 事件只驱动 UI 状态，正常回复结束不得修改远端播放订阅。
- 状态不能只依赖颜色，必须同时使用统一图标、明确文案或形态变化；所有可操作控件均可键盘访问并有 `focus-visible`。

### 3.3 设备与隐私控制

- 设置提供设备列表，每项显示设备名、平台、凭证状态和过期时间；点击“撤销设备”必须二次确认，确认后立即使该设备凭证失效，结束当前会话并回到 `IDLE`，其他设备不受影响。
- 转写默认不持久化。用户显式开启“本地加密保存”后，设置页提供本地删除与导出；删除需显示影响范围并二次确认，导出前显示文件范围和保存位置。
- 诊断导出仅包含脱敏指标与事件（例如时延、状态转换、错误类别和重试次数），明确不含凭证、原始音频、截图、代码或完整敏感文本；导出前显示该边界。
- 第三方云端、麦克风、后台对话、桌面捕获四个开关必须可见且可访问；关闭任一开关即时生效，立即停止对应录音或截图，并显示当前影响（例如“仅保留文字输入”“后台唤醒已关闭”）。
- 隐私开关变化只更新对应能力与 `VoiceUiModel` 可见文案，不新增会话生命周期或体验状态；`interrupted` 仍是体验状态机内的瞬时状态。

## 4. 错误恢复

| 场景 | 用户反馈 | 系统恢复 |
|---|---|---|
| 签发失败 | “无法建立安全会话，请重试” | 回到 `IDLE`，保留入口可用，不进入退出锁 |
| 进入房间超时 | “连接超时，正在重新连接” | 有限次数重试；失败后回到 `IDLE` |
| 中继断线 | 显示离线状态与重连进度 | 1、2、4、8、16、30 秒指数退避，重连后重新握手 |
| 下行无声 | 显示播放异常与重试操作 | 保持订阅，重建播放缓冲，不以静音作为恢复手段 |
| 本地模型不可用 | 明确显示全双工主链路不可用及恢复操作 | P0 不得自动降级并伪装为全双工；半双工仅作为用户显式选择的 P1 兼容模式独立进入 |
| 麦克风权限缺失 | 指明缺失权限及设置入口 | 暂停监听，保留通知与手动恢复入口 |
| 电量低于 15% | 说明已暂停常驻监听 | 保留通知按钮，充电或用户确认后恢复 |
| 连续失败 | 展示可操作的错误摘要 | 提供重试、退出会话；不得暴露 token、堆栈或内部服务地址 |

所有错误文案必须描述具体故障和下一步动作，不使用空洞占位或笼统的“出错了”。录音不得落盘或进入日志；重连不得重复注入已经确认的任务。

## 5. Token 与统一 SVG 图标系统

### 5.1 Design Token

- 所有组件颜色必须通过 Design Token 引用。除 Token 定义文件外，组件和样式中禁止出现 hex、rgb、rgba 字面量。
- 深色界面采用冷调中性色、一个天蓝强调色及成功、警告、危险语义色；强调色每屏最多两处可见使用。
- 宠物仅允许深蓝到天蓝的同色系渐变。禁止紫色到粉色渐变、渐变文字、装饰性毛玻璃和发光边框堆叠。
- 间距遵循 4px 网格；卡片圆角不超过 16px；交互反馈使用 150 至 300ms 动效。
- 必须实现 `focus-visible`、键盘可达和 `prefers-reduced-motion`。降级动效后仍保留图标与文案语义；reduced-motion 下关闭持续波形、脉冲和非必要位移动画。
- 字体明确使用显示、正文、等宽三层栈；建议正文使用 Noto Sans SC，状态码、耗时和数字列使用 JetBrains Mono，展示字体使用 MiSans（落地前确认授权）；跨端固定 400/510/590 字重层级。
- Token 按四层维护：A1-identity（`--bg/--surface/--fg/--muted/--accent/--border/--font-*`）、A1-structure（字号、容器、节区节奏）、A2（`--success/--warn/--danger/--motion-* / --focus-ring`）、B-slot（`--fg-2/--meta/--surface-warm/--border-soft`）；C-extension 仅允许品牌特有且登记的别名。
- 中性色占主要界面面积（目标≥90%），`--accent` 每屏最多两处；页面和组件只能引用语义 Token，裸 hex/rgb/rgba 仅允许集中在 Token 定义文件。

### 5.2 图标系统

- 全项目锁定 Lucide SVG 图标系统，不得混用其他图标库。
- Android 使用与 Lucide 同语义、同描边语言的 vector drawable。
- 统一尺寸：16px 行内、20px 按钮内、24px 独立图标。
- 图标按钮必须提供可访问名称和可见焦点状态。
- 禁止使用 emoji 作为功能图标。

### 5.3 P0 禁令

以下任一项出现即不通过：

- emoji 功能图标；
- 紫色到粉色渐变；
- Token 文件之外的硬编码颜色；
- 空洞文案或无具体动作的占位提示；
- 虚假 Hero，包括口号、居中 CTA 和抽象装饰构成的模板首页。

产品首屏必须直接呈现可操作的监控、语音或状态体验，不制作营销式假 Hero。

## 6. 机械验收标准

1. 可执行基线：sidecar 依赖干净安装，`npm ls` 退出码为 0；运行日志能输出真实 SDK 版本；sidecar 冒烟启动成功。
2. 状态机：自动化测试覆盖签发期快速取消、进房超时、重复点击、退出、重进和服务停止；任何路径最终均可回到 `IDLE`，不存在永久退出锁。
3. 真机双工：至少一台 Android 真机连续完成两轮对话；每轮均有非零本地采集、上行帧、下行帧、远端首帧及实际播放证据；第二轮仍可听见。
4. 实时音频：PCM 跨模型块缓存，仅发送完整固定 20ms 帧；上下行队列有界，过载时丢旧保新，并暴露队列深度与帧龄指标。
5. 安全与 P0：会话签发具备设备身份、sidecar 服务身份、限流、nonce 或短期请求签名；静态扫描确认无 emoji 功能图标、无紫粉渐变、无组件硬编码色、无空洞文案和假 Hero。
6. 双层状态与单一模型：静态扫描禁止通过 `isListening`、`isThinking`、`isSpeaking`、`inCall`、`rtcExiting` 等并行业务布尔拼装 UI；状态测试覆盖所有声明的合法转换与非法转换拒绝，且 Android 与桌面只消费同一 `VoiceUiModel`。
7. 三入口与触控可用性：Android 主会话页、悬浮球、前台通知“立即对话”分别执行独立可重复测试，均进入同一 TRTC lifecycle；任一入口故障时另外两个仍可发起对话。唤醒词仅为 P1 Beta，不参与 P0 门禁。Android 主页面、悬浮球、通知操作及桌面所有可操作控件的触摸或点击目标均不小于 44 x 44px，并通过键盘/屏幕阅读器可访问性扫描。
8. 下行无声诊断：每轮会话以 `session_id`/`turn_id` 关联并记录非零下行帧、远端首帧、播放缓冲、音频焦点和扬声器播放证据；正常远端停止事件不得触发 `mute`，下一轮回复仍必须保持播放订阅。
9. 打断验收：在 `speaking` 状态真机开口后，视觉状态进入 `interrupted`，P95 在不超过 300ms 内停止播报；`pause`、`flush`、`interrupt` 操作必须幂等，流程最终回到 `listening`。
10. 错误与恢复：对签发、进房、中继、模型、麦克风五类故障分别注入测试；每类均显示分类原因和可执行操作，有限重试耗尽后可回到 `IDLE`，允许保留的草稿/上下文不丢失且凭证不泄露。
11. 设备撤销：设置设备列表逐项展示设备名、平台、凭证状态和过期时间；撤销操作必须出现二次确认，确认后凭证立即失效、当前会话结束并回到 `IDLE`，自动化测试确认其他设备仍不可受影响。
12. 隐私控制：默认转写持久化为关闭；开启本地加密保存后，本地删除与导出均可执行并有范围确认。诊断导出静态扫描与样本检查确认只含脱敏指标/事件，不含凭证、原始音频、截图、代码或完整敏感文本；第三方云端、麦克风、后台对话、桌面捕获开关分别测试关闭即时生效，录音/截图立即停止且界面显示影响。
