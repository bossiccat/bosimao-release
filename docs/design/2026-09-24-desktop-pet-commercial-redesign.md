# 桌面端（pet-ui）商业化重做 — 设计规格（锁定）

> 2026-09-24。触发：用户「不要给我修修补补。必须按照最专业的商业化标准重做」。
> 状态：**已锁定**。实现必须逐条满足第 7 节的验收标准，不接受"改配色/换 token"式修补。
> 现状诊断（证据）：窗口 200×200 透明无边框；idle 态整块 UI = 一幅 **80px 手写几何 SVG**
> （三角耳 `M31 46 L25 22 L44 33 Z`、椭圆脸、`r=3.5` 圆点眼、两段二次曲线 w 形嘴、4 根直线胡须，
> 描边 1.5–2 ⇒ 实际约 1.2 设备像素）+ radial 光晕 + drop-shadow + 呼吸环。
> 上一轮（09-16）只改了 token 配色，**按构造不可能改善这幅画** —— 这就是"还是不行"的原因。

---

## 1. 产品定义与场景

桌面常驻桌宠（Windows，Tauri，`transparent + decorations(false)`）。三种使用场景：

| 场景 | 用户在看到什么 | 设计目标 |
|---|---|---|
| 常态（占 95% 时间） | 屏幕上只有一只宠物 | **这一只宠物必须达到商业插画水准** —— 它是产品的门面 |
| 交互态（悬停） | 宠物 + 一小组控件 | 控件克制、可达（≥44px）、不遮挡宠物 |
| 任务态（面板） | 宠物 + 状态/设置/故障面板 | 面板是标准产品 UI，密度合理、层级清晰 |

**结论性判断：常态观感 = 宠物插画质量决定。** 面板做得再好也救不了"屏幕上只有一幅剪贴画"。

## 2. 视觉语言（锁定，不得偏离）

- **品牌**：白底 + 绿主色。`--accent #16a34a`（已在 token 中，保留）。
- **窗底**：`transparent: true` 保持；因此**不得依赖窗外阴影/背景**，观感必须**只靠宠物本体**成立。
- **宠物配色（新增，必须进入设计 token）**：
  - 毛基色 `--pet-fur-base`：暖白 `#fbfaf7`
  - 受光面 `--pet-fur-light`：`#ffffff`
  - 背光面 `--pet-fur-shade`：`#e8ece6`（**带绿倾向的中性灰，不许用纯灰**）
  - 深阴影 `--pet-fur-deep`：`#cbd6cc`
  - 描边 `--pet-outline`：`#5b6b60`（**不许纯黑**；商业插画不用 100% 黑描边）
  - 内耳/鼻 `--pet-inner`：`#e9b8b6` / `#d98c8c`
  - 眼 `--pet-eye`：`#2b3a30`；虹膜高光 `#ffffff`
  - 项圈（品牌触点）`--pet-collar`：`--accent`；吊牌 `#f5c451`
- **字号/间距/圆角/动效/高度**：**全部复用** `pet-ui/src/styles/design-tokens.css`（418 处 `var(--)` 已在用，不要另立一套）。

## 3. 宠物插画规格（本次重做的核心）

- **画布**：`viewBox="0 0 240 240"`（不是 100×100 —— 预留阴影与毛边）。
- **渲染尺寸**：常态 **152px**（不是 80px）；提醒态 **176px**。`sizePx` 默认值改为 152。
- **必须是一只完整的猫，不是一张脸**：头 + 躯干 + 前爪 + 尾巴（波斯猫：扁脸、短鼻、圆头、蓬松尾）。
- **必须有的图层（缺一项即退回）**：
  1. 地面接触阴影（椭圆，低透明度，营造"坐着"而非"飘着"）
  2. 尾巴（卷曲，与躯干有前后遮挡关系）
  3. 躯干 + 前爪（前爪要有趾间分隔线）
  4. 头（圆头 + 腮部空气感），**受光/背光两档明暗**，不是单色填充
  5. 立耳 ×2：外耳 + **内耳（异色 + 耳廓毛线）**
  6. 眼 ×2：眼白/虹膜/瞳孔/**高光点**（高光是"活"的关键，不得省）
  7. 鼻 + 嘴（上唇分叉的 y 形，不是"w"形抽搐线）
  8. 胡须 ×6：**两端收细的曲线**（锥形），不许是等粗直线
  9. 项圈 + 吊牌（品牌绿，极小的品牌触点）
- **描边**：闭合轮廓用 `--pet-outline`，**粗细随部位变化**（外轮廓 2.5、内部结构线 1.5），
  不许全身一个 `strokeWidth`。描边用 `stroke-linejoin/linecap: round`。
- **禁止**：纯几何拼贴感（正三角耳、正圆眼、直线胡须）；`filter: drop-shadow` 糊边；
  纯黑描边；单色平面填充。

## 4. 状态（同一套插画的差异化表现，不是换描边色）

| 状态 | 视觉语言 |
|---|---|
| `idle` | 眨眼（每 4–7s 一次，120ms）、耳尖极轻摆动、尾尖慢摆、呼吸（scale 1→1.015） |
| `listening` | 双耳前倾、瞳孔放大、项圈呼吸发光（`--accent`，低强度） |
| `thinking` | 头微侧倾 + 尾巴加速摆动 + 头顶三点（SVG 圆点，非 emoji） |
| `speaking` | 嘴部开合（3 帧循环）+ 身体随语音轻微起伏 |
| `alerting` | 全身提亮、瞳孔收缩、耳朵后压、语义色环（沿用 `--voice-*`） |

`reduced-motion`：全部动画降为静态 + 仅颜色/不透明度变化（现有 `@media` 保留）。

## 5. 面板与控件（标准产品 UI，不是"卡片浮在透明窗上"）

- 状态胶囊 `ConnectionBadge`：单行、图标 16px（**lucide-react，已是锁定图标库**）+ 文案，高 32px。
- 控件组：**图标按钮 40×40、圆角 `--radius-lg`、描边 1px `--border`**；hover/active/focus 三态齐全
  （focus 用 `--focus-ring`，已定义）。
- 面板（监控/设置/CA 确认/故障横幅）：白底卡片 + `--elev-raised` + 内边距 `--space-5`；
  **标题 15px/600、正文 13px/400、说明 12px `--muted`**；行高 `--leading-compact`。
- **故障横幅不许用 2px 纯红描边压满**：改为浅红底 `--danger` 8% + 1px 描边 + 图标 + 主/次动作。
- 面板尺寸沿用 `App.tsx` 既有契约（面板 380×480 / 设置 380×560 / CA 400×580 / 故障 440×220）。

## 6. 工程约束（违反即退回）

- 文件 ≤ **300 行**（仓库契约 `authored operational JavaScript modules stay within 300 lines`）。
- **颜色只能来自 token**（唯一例外 `#fff`/`#000`）；新增颜色必须先加到 `design-tokens.css`。
- **禁止 emoji 作图标**；图标一律 `lucide-react`。
- **禁止**运行时内联 `<style>`（当前 `Pet.tsx` 有此问题）——样式进 `src/styles/`。
- 保留既有语义契约：`.pet` / `.pet-alert-pulse` / `data-testid`：`pet-face`、`pet-shell`、
  `pet-ear-left`、`pet-ear-right`、`pet-face[data-tone]`（`src/test/Pet.test.tsx`）。
- 组件不得因重做而丢失 `reduced-motion` 与 `aria-hidden` 处理。

## 7. 验收标准（逐条，且必须有**渲染截图**佐证）

1. 常态在 **200×200 透明窗**内渲染：宠物完整、居中、有地面阴影，**肉眼无像素化/糊边**。
2. 在 **152px** 与 **380×480 面板态**两种尺寸下各出一张渲染图。
3. 五种状态（idle/listening/thinking/speaking/alerting）各出一张。
4. 全仓扫描：组件内 emoji 图标 = 0；非 token 色值 = 0；运行时内联 `<style>` = 0。
5. `npx vitest run` 全绿；`Pet.test.tsx` 既有断言不改语义。
6. `npm run build` 通过；产物在 Chrome 里按 200×200 与 480×480 渲染截图归档。
7. 由**非实现者**按第 3–6 节逐条复核并给出 pass/fail（verifier 角色）。

## 8. 分工

| 角色 | 职责 |
|---|---|
| 插画（art） | 第 2 节配色 + 第 3 节插画 + 第 4 节状态；产出可用的 SVG/组件 + 各状态渲染图 |
| 应用壳（shell） | 第 5 节面板/控件 + 第 6 节工程约束；保证尺寸契约与既有测试 |
| 复核（verify） | 第 7 节 1–6 条逐条复核，独立出图，不给"看起来不错"这种结论 |
