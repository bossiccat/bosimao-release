## 四、关键发现

### ✅ 无新增 P0/P1 缺陷

Round 2 的 10 个场景未发现任何 P0/P1 缺陷。Round 1 修复的 2 个 P1（意图协调误报、顶替竞态）在 Round 2 的相关场景中持续稳定：
- S16/S17 验证了意图协调的过期清理和双重消费防竞争——Round 1 P1-1 修复持续有效
- S12 的 20 次快速重连验证了顶替语义——Round 1 P1-2 修复持续有效

### 🟡 环境因素（非代码缺陷）

1. **Sidecar 自动重连干扰**：S15 长会话测试中，sidecar 不断重连顶替测试连接（56 次重连）。测试脚本加入 ResilientWS 自动重连容错后通过。这验证了 bridge 的顶替逻辑在高压下正常工作，但也说明**压测环境需先停 sidecar**（Round 1 QA 复核已记录此待办）。
2. **Sidecar 抢消费意图**：S16 首跑时 sidecar 抢消费了部分测试意图。判定逻辑改为验证语义正确性（创建后可见、消费后消失、二次消费拒绝）而非精确数字。重跑时 sidecar 未干扰（5/5 可见）。

### ✅ 稳定性亮点

1. **内存零增长**：S12（20 次重连）和 S15（60s 长会话）内存增量均为 **0.0MB**——无内存泄漏。
2. **畸形输入全吞**：S15 种畸形消息全部被 bridge 静默处理（`json.JSONDecodeError` continue / 未知 type debug log / 无效 base64 warning），bridge 未崩溃。
3. **超大帧不 OOM**：1MB 音频帧（正常 640B 的 1600 倍）成功处理，bridge 未 OOM。
4. **健康端点极快**：100 并发 /health + /metrics 仅 **0.044s**——asyncio 原生 HTTP 服务性能优秀。
5. **后端故障不崩**：APM 后端不可达时，bridge 吞异常继续运行，apm 状态正确标记为 "closed"。
